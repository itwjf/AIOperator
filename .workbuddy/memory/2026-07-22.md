## Bug 排查 #1：400 tool_calls 错误（对话/诊断/MCP 三种模式）
- 报错：assistant message with 'tool_calls' must be followed by tool messages
- 根因定位：app/core/message_trimmer.py 的 trim_conversation_history 函数缺陷
  - 只处理了"开头是孤立 ToolMessage"（删开头 ToolMessage）
  - 未处理"开头是带 tool_calls 的 AIMessage，但其 ToolMessage 响应被裁掉"
  - 滑动窗口 messages[-20:] 裁剪后，若第一条恰是 AIMessage(tool_calls)，
    对应 ToolMessage 在窗口外 → 孤立 tool_calls → DashScope 400 拒绝
- 影响范围：
  - RAG Agent（MessageTrimmerMiddleware）→ 必现
  - MCP Agent（MessageTrimmerMiddleware）→ 必现（工具多更易超 20 条触发）
  - 手动 Agent（call_model 内 trim）→ 同源 bug，但工具少触发概率低（定时炸弹）
  - AIOps executor（create_agent 无 checkpointer 无 middleware）→ 需进一步确认
- 为什么云服务器才出现：服务持续运行，MemorySaver 累积对话超 20 条触发修剪
- 修复方向：trim_conversation_history 增加"删除开头孤立 AIMessage(tool_calls)"逻辑
  或改用 langchain_core 的 trim_messages 官方工具（自带 tool_call 配对保护）

## 风险点排查 #1：MemorySaver 内存存储
- 四个 Agent service 都用 MemorySaver（纯内存），重启即丢失对话历史
- 是 Bug #1 在云服务器才暴露的帮凶（内存累积超 20 条触发修剪）
- 修复方案：改用 SqliteSaver（langgraph-checkpoint-sqlite），持久化到文件
  - 需在 pyproject.toml 加依赖 langgraph-checkpoint-sqlite
  - Docker 需挂载 volume 持久化 .db 文件
  - 每个 service 用独立 db 文件避免会话冲突
